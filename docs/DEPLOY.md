# Развёртывание SLAVIA ROLEPLAY

Три самостоятельных PHP-приложения, **PHP 8.1+**, HTTPS, отдельные хосты:

| Приложение | Document root | Установка |
| --- | --- | --- |
| Сайт | `Сайт/` | `/admin.php` |
| Форум | `Форум/public/` | `/install.php` |
| Wiki | `Вики/public/` | `/install.php` |

**Не размещайте весь Git-репозиторий в веб-корне.**

## Защита приватных данных

Для **Apache 2.4+** файл `Сайт/private/.htaccess` запрещает HTTP-доступ к `/private/`. Убедитесь, что сервер действительно обрабатывает `.htaccess`. Для **Nginx** это правило не действует. Добавьте:

~~~nginx
location ^~ /private/ {
    return 404;
}
~~~

Проверьте снаружи, что `https://ваш-домен/private/data/settings.php` и `/private/core.php` недоступны (403/404). PHP-защита в файлах **не заменяет** запреты веб-сервера.

Для форума и Wiki каталоги `app/` и `storage/` должны находиться вне их `public/` корней.

## Ключи установки

Ключи создаются **на хостинге**, без хранения в Git:

| Приложение | Файл ключа |
| --- | --- |
| Сайт | `Сайт/private/data/.install-key.php` |
| Форум | `Форум/storage/.install-key.php` |
| Wiki | `Вики/storage/.install-key.php` |

Узнайте ключ через защищённый SSH/SFTP, укажите его в форме установки. Либо задайте переменные окружения `SLAVIA_SITE_INSTALL_KEY`, `SLAVIA_FORUM_INSTALL_KEY`, `SLAVIA_WIKI_INSTALL_KEY` (уникальные значения не короче 32 символов). Старые ключи были опубликованы в истории Git; их **нельзя использовать снова**. Установленные ранее аккаунты и пароли нужно проверить.

## Внимание при обновлении существующего сайта

**Прежде чем выполнить `git pull`, сделайте резервную копию `Сайт/private/data/`.** Ранний репозиторий отслеживал `settings.php`, `news.php`, `faqs.php`, `products.php`, `servers.php` и `tickets.php`. Теперь эти файлы считаются runtime-данными и исключены из Git; PHP создаёт шаблонные значения при первом запуске. При обновлении старой установки Git **может удалить неизменённые версии этих файлов**, поэтому обязательно восстановите свои настройки, обращения и новости из бэкапа и не храните пользовательские данные в Git.

Также сделайте резервные копии `Форум/storage/`, `Вики/storage/` и SQLite игрового мода. Проверьте права записи веб-процесса.

Локальные проверки: `bash tests/repository.sh` и `bash tests/smoke.sh`. Они не заменяют нагрузочное тестирование и аудит. Статусы серверов на сайте задаются вручную; интеграция платежей, клиента и игрового API пока отсутствует.
