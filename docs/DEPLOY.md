# SLAVIA ROLEPLAY — развёртывание

Три самостоятельных PHP-приложения в одном репозитории. Проверка CI выполняется на PHP 8.2; для размещения нужен PHP 8.1+ с поддержкой JSON и sessions.

| Часть | Папка в Git | Корень сайта (document root) | Установка |
| --- | --- | --- | --- |
| Сайт | `Сайт` | `Сайт/` | `/admin.php` |
| Форум | `Форум` | `Форум/public/` | `/install.php` |
| Wiki | `Вики` | `Вики/public/` | `/install.php` |

Перед первым запуском настройте три отдельных хоста или поддомена и HTTPS. Для сайта на Apache используйте правила `.htaccess`: они запрещают веб-доступ к `private`. При использовании Nginx **запретите доступ к `/private/` целиком**, включая файлы данных. Для форума и Wiki директории `app/`, `storage/` должны оставаться *за пределами document root*.

## Первый запуск и секреты

У каждого приложения автоматически создаётся **свой случайный ключ установки**, он **не хранится в репозитории** и не отображается посетителям:

- Сайт: `Сайт/private/data/.install-key.php`
- Форум: `Форум/storage/.install-key.php`
- Wiki: `Вики/storage/.install-key.php`

Впервые откройте страницу установки, затем прочитайте содержимое соответствующего файла **через SSH/SFTP или файловый менеджер хостинга**. Скопируйте строку между одинарными кавычками в поле ключа на странице установки. Никогда не размещайте секрет в чате, логах или Git. Если хостинг поддерживает переменные окружения, можно вместо файла задать уникальное значение длиной не менее 32 символов: `SLAVIA_SITE_INSTALL_KEY`, `SLAVIA_FORUM_INSTALL_KEY`, `SLAVIA_WIKI_INSTALL_KEY` соответственно.

Ранее в публичную историю репозитория были загружены ключи первоначальной установки. **Они скомпрометированы и не должны использоваться.** Новая версия создаёт другие ключи при первом запуске; на ранее развёрнутых экземплярах проверьте администратора и смените все пароли. Не пытайтесь «скрыть» старые ключи только удалением из последнего коммита.

## Данные и резервные копии

Права на запись требуются для `Сайт/private/data`, `Форум/storage` и `Вики/storage`. Данные форума/Wiki и ключи не должны попадать в Git. Сайт пока хранит часть исходных *шаблонных* данных в `private/data` (они загружены в репозиторий для первоначального наполнения); не публикуйте живые обращения/учётные записи и сделайте резервную копию перед обновлением из Git.

Перед каждым развёртыванием сохраните бэкап файлов хранения, затем проверьте формы, авторизацию, HTTPS и логи PHP. Не запускайте проект как публичный production-сервис без ревизии безопасности и нагрузочных тестов: JSON-хранилище подходит для небольшой нагрузки, но не заменяет СУБД при большом количестве игроков.

Серверы, клиент игры, магазин и домены подключаются отдельно — в исходной сборке нет действующей интеграции с игровым сервером или платёжным провайдером.
