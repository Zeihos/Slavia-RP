# Внесение изменений

1. Откройте Issue с описанием задачи или воспроизведения ошибки.
2. Создайте ветку `feat/...`, `fix/...` или `chore/...` от `main`.
3. Изменяйте только относящийся к задаче компонент; не переименовывайте корневые каталоги без обновления путей.
4. Откройте PR: укажите, что сделано, какие тесты реально выполнены, какие риски остались.
5. Дождитесь GitHub Actions. Для изменений в интерфейсе приложите скриншоты *из браузера*, для игры — логи тестового сервера.

**Локальные проверки:** `bash tests/repository.sh`, `bash tests/smoke.sh` и `php -l` для изменённых PHP-файлов; `sampctl ensure && sampctl build` в папке `Игра`.

Нельзя коммитить пароль, токен, личные данные игрока, сохранение, реальные жалобы, бинарные сборки и закрытые сторонние исходники без прав на распространение. См. [сторонние материалы](./docs/THIRD_PARTY.md).
